산출물: 정적 사이트 (Vercel/GitHub Pages 무료 티어) - `index.html` + `privacy.html` (P0 겸용).

SkinMe 웹 랜딩 페이지를 만들어줘. 정적 HTML/CSS(+최소 JS) - 프레임워크·빌드 도구 없이 파일 그대로 배포 가능하게.

## 0. 제품 정체성 (모든 결정의 기준)
- 한 줄: 셀카로 피부 점수를 측정해, 지금 쓰는 화장품이 진짜 효과 있는지 14일 만에 숫자로 판정하는 앱
- 메인 카피: "거울은 매일 거짓말을 합니다."
- 보조 카피: "같은 순간을 두 번 재면 같은 숫자가 나옵니다." (재현성 전 지표 오차 0 - 실측 사실)
- 포지셔닝: 심판은 물건을 팔지 않는다 - 광고·커머스·제품추천 완전 배제. 이 중립성이 신뢰의 근거
- 페이지의 단 하나의 목표: 앱 설치 버튼 클릭. 나머지 전부는 그 설득 과정

## 1. 美學 - "밝은 계측기" (앱과 동일, 타협 금지)
- 화이트 베이스(#ffffff), 카드 배경 #F8F9FA, 보더 #E5E7EB
- 포인트 컬러 단 1색: 민트 #10B981 (밝은 변형 #4ADE80) - CTA·활성 상태·개선 수치에만
- 텍스트: #111111(주) / #374151(부) / #6B7280(설명) / #9CA3AF(미세)
- 숫자가 히어로: 위계는 색이 아니라 크기·굵기·여백으로. 숫자는 tabular-nums, 큰 숫자는 700 굵기
- 레퍼런스: 애플 건강, 토스 - 데이터가 주인공인 절제된 화면
- 금지: 파스텔 다색, 일러스트, 이모지, 스톡 사진, 그라데이션 남용, 빨강(악화 상태만 #F59E0B 앰버)
- 여백 넉넉히(섹션 간 96px+), 8pt 그리드, 라운드 12~16px, 그림자는 은은하게(카드 1단계)
- 폰트: Pretendard(CDN) 또는 시스템 폰트 스택 - 본문 15~17px, 히어로 카피 40px+/모바일 28px+

## 2. 페이지 구조 (스크롤 순서 그대로)
### ① 히어로
- "거울은 매일 거짓말을 합니다." 한 줄이 화면을 지배 - 장식 없이 타이포만
- 서브 한 줄: "조명과 기분에 따라 달라 보이는 피부, 같은 조건으로 재면 진짜 변화가 보입니다"
- CTA 버튼 1개: "무료로 측정하기" (민트, 라운드 필, Play 스토어 링크 - href는 PLACEHOLDER_STORE_URL)
- 배경에 아주 옅은 동심원 그리드(계측기 모티프, opacity 5% 수준) 허용 - 유일한 장식

### ② 재현성 증명 (신뢰 섹션)
- "같은 순간을 두 번 재면 같은 숫자가 나옵니다"
- 시각 장치: 두 번의 측정 카드가 나란히 - 동일한 점수(예: 78 / 78)가 크게. 숫자가 곧 증거
- 캡션: "동일 조건 2회 측정, 전 지표 오차 0 - 타원 가이드와 화면 플래시로 촬영 조건을 고정합니다"

### ③ 어떻게 작동하나 (3스텝)
- 촬영(타원 가이드 SVG 미니 비주얼) → 5점 밴드 점수 → 14일 뒤 판정 리포트
- 각 스텝: 번호·아이콘 대신 얇은 라인 도형(타원·숫자·그래프 선), 설명은 각 2줄 이내
- 리포트 미리보기: "개선 +7" 스타일의 판정 카드 목업(HTML/CSS로 직접 그림 - 이미지 파일 아님)

### ④ 중립성 선언 (차별화 섹션)
- "심판은 물건을 팔지 않습니다" - 광고 없음·제품 추천 없음·데이터 판매 없음 3줄
- 사진 처리 원칙 병기: "사진은 분석 후 즉시 삭제됩니다 - 저장되는 건 숫자뿐"

### ⑤ 가격 (투명하게)
- 무료: 하루 1회 측정 + 종합·항목별 점수 / Pro: 근거·추이·14일 판정 리포트
- 실청구액 표기: 월 4,900원 / 연 39,000원(월 3,250원꼴) · 14일 무료 체험 · 자동갱신 명시
- 가격 은닉 금지 원칙 그대로 - 접거나 숨기지 않는다

### ⑥ 마지막 CTA + 푸터
- 카피 반복 + 설치 버튼
- 푸터: 개인정보처리방침 링크(privacy.html) · 문의 메일 · © SkinMe

## 4. 기술 요구
- 파일: index.html, privacy.html, style.css (JS는 스크롤 페이드인 정도만 - 없어도 무방)
- 반응형: 모바일 우선(릴스에서 유입되는 트래픽 = 90% 모바일). 360px~데스크톱
- 성능: 외부 의존성 최소(폰트 1개), 이미지 없이 CSS/SVG로 그림 - LCP < 1.5s 목표
- 링크: 스토어 버튼에 UTM 파라미터 패스스루(?utm_source= 등이 붙어 와도 유지되어 스토어 링크에 전달)
  - 분석 스크립트·쿠키·트래커는 넣지 않는다 (중립성·프라이버시 포지셔닝과 일관)
- 언어 원칙: 문구의 주어는 유저의 상황·목적 (기능 자랑 ❌ / "효과를 알아볼 수 있어요" ⭕). 감탄사·번역투 금지
- SEO 기본: title/description/og 태그 (og 이미지는 PLACEHOLDER), lang="ko"

## 사용법
1. 위 블록 복붙 → 실행 (Fable/Opus 무관, 렌더 검증 루프 포함돼 있음)
2. 산출물을 Vercel 또는 GitHub Pages에 업로드 (사용자)
3. 배포 URL 확정 후:
   - `app/settings.tsx` PRIVACY_URL → `https://<도메인>/privacy.html`
   - 공유 카드(ShareableScoreCard·ShareableCard) 하단에 랜딩 URL 한 줄 추가 (future-backlog 7번)
   - Play Console 등록정보에 처리방침 URL 등록
4. PLACEHOLDER 채우기: 스토어 URL(출시 후), 문의 이메일, 시행일, og 이미지

## 이 프롬프트의 의도
- 美學 섹션을 수치(헥스·픽셀·굵기)로 못 박아 "느낌대로" 해석할 여지 제거
- 페이지 구조를 설득 순서(카피 → 증명 → 작동 → 중립성 → 가격 → CTA)로 고정 - 마케팅 관문의 정석
- 트래커·분석 스크립트 배제 = 프라이버시 포지셔닝을 랜딩에서도 일관되게
- privacy.html 동봉으로 P0-1(처리방침 호스팅)을 한 번에 해결
