"유저 축적 이후"에만 의미 있는 항목들. 각 항목은 착수 조건이 충족될 때 프롬프트를 그대로 사용.

## 1. 성별·나이대 분포 비교 ("또래 대비 위치") - 백로그 캘리브레이션의 구체화

**착수 조건**: 성별×나이대 셀당 유저 수백 명 이상 축적 (그 전엔 분위수가 무의미).
**철칙**: 수집 데이터는 표시 레이어 전용 - 분석 프롬프트 주입 절대 금지 (전원 동일 측정 기준 = 재현성 자산 보호).
**수집 시점**: 지금 미리 받지 않는다. 이 기능을 만들 때, 이 기능 화면에서 용도를 보여주며 수집 (동의율 최대 시점 + 수집 최소화 포지셔닝 유지).

**실행 프롬프트:**
```
"또래 대비 내 피부 위치" 기능을 구현해줘. 절대 조건: 성별·나이대는 분석 프롬프트·점수 파이프라인에
넣지 않는다 - 표시 레이어(분포 비교)에서만 사용. computeVerdict·analyze-skin 무변경.

1. 수집 UI: 오늘 탭 점수 아래 "또래와 비교해보기" 카드 → 탭하면 나이대(10대~50대+)·성별(남/여/선택 안 함)
   선택 시트. 용도 한 줄 명시: "비교 표시에만 쓰여요". 선택 안 함이어도 전체 분포와는 비교 가능
2. 저장: profiles 테이블 신규 (user_id PK, gender text null, age_band text null, created_at, updated_at).
   RLS 본인 행 select/insert/update. 처리방침·Play 데이터 보안 폼 반영 항목을 보고서로 동봉
3. 분포 산출: 서버측 집계 (pg_cron 일 1회 → metric_distributions 테이블: 성별×나이대×지표별
   p10/p25/p50/p75/p90). 개별 유저 데이터 노출 금지 - 집계 테이블만 클라이언트 select 허용,
   셀 표본 100명 미만이면 해당 셀 미제공(재식별 방지 + 통계 신뢰)
4. 표시: 지표 상세에 "같은 20대 여성 중 상위 30%" 한 줄 + 분포 막대 위 내 위치 점. Pro 전용
5. 내 점수·판정에는 어떤 영향도 없음을 화면과 코드 주석 양쪽에 명시
6. 수집 거부/미입력 유저의 기존 경험은 완전 동일 유지

검증: 집계 SQL Docker 테스트(표본 미달 셀 제외 케이스 포함), 분위 계산 노드 테스트, tsc.
처리방침 개정 문구 초안 동봉.
```

## 2. iOS 출시 트랙 (W3 후반~)

**착수 조건**: Android 출시 안정화 후. 세션 중 문서화된 iOS 리스크가 이미 코드 주석에 존재.

**실행 프롬프트:**
```
iOS 출시 준비를 일괄 진행해줘. 빌드 실행은 내가 한다 - 준비까지만.
1. RevenueCat iOS 키 배선 (purchases.ts의 Android 전용 분기 해제) + App Store 상품·entitlement 체크리스트
2. 계정 연동에 Apple 로그인 추가 (Google만 있으면 iOS 심사 거절 - Sign in with Apple 요구사항)
3. 코드 주석에 문서화된 iOS 차이 실기기 검증 시나리오화: ① 조도 폴백(2초 스냅샷)의 프리뷰 끊김·셔터음
   ② setBrightnessAsync 전역 밝기 + 강제종료 잔존 ③ 연사 2컷 간격 (docs/ios-test-checklist.md 갱신)
4. App Store 심사 대비: 개인정보 영양표(사진 미보관 명시), 구독 표기(실청구액·갱신), 계정 삭제 요건
5. iOS에서 조도 폴백이 심사·UX상 부적격 판정이면 vision-camera 전환 견적 보고 (구현은 별도 결정)
검증: tsc + iOS 시뮬레이터 스모크 절차 안내 (카메라·밝기는 실기기 항목으로 분리 명시).
```

## 3. 데이터 내보내기 (신뢰 포지셔닝 강화)

**착수 조건**: 출시 후 여유 시점. "내 데이터는 내 것" - 사진 미보관 원칙과 한 쌍이 되는 신뢰 장치.

**실행 프롬프트:**
```
기록 내보내기를 구현해줘. 설정 화면 "내 데이터 내보내기" 행 추가.
1. 형식: JSON 1파일 (scans 전체 + products/verdict 전체, 서버 result 원본 그대로) - 사진은 애초에 없음
2. expo-sharing으로 공유 시트 내보내기, 임시 파일은 공유 후 삭제
3. 페이지네이션으로 전체 조회 (현 useScans는 10개 제한 - 별도 전량 쿼리)
4. 실패 처리·로딩 상태·strings.ts 등록. Pro 게이트 없음 (본인 데이터 접근은 무료 원칙)
검증: tsc + 내보낸 JSON을 zod 스키마로 재검증하는 노드 테스트.
```

## 4. 프롬프트 버전 전환 안전장치 (점수 스케일 연속성)

**착수 조건**: v0.8 이후 프롬프트 대개편(지표 정의 변경급)이 필요해질 때. 지금 프롬프트 버전은 저장 안 됨 - 히스토리 비교 오염 리스크.

**실행 프롬프트:**
```
프롬프트 버전 전환 안전장치를 구현해줘.
1. scans에 prompt_sha text 컬럼 추가, analyze-skin insert 시 SKIN_ANALYSIS_PROMPT_SHA 기록
   (기존 행 null 허용 - 소급 불가는 수용)
2. 대개편 배포 전 절차를 docs에 명문화: canary 3장에서 신·구 버전 병렬 분석 → 지표별 편차 표 →
   편차 >5인 지표가 있으면 "스케일 단절"로 분류
3. 스케일 단절 시 클라이언트 처리: 추이 그래프에서 버전 경계에 점선 단절(기존 held 단절 패턴 재사용),
   computeVerdict는 기준선과 비교군의 prompt_sha가 다르면 리포트에 "측정 기준 변경 구간" 주석 표시
   (판정 로직 자체는 무변경 - 표시만)
검증: 마이그레이션 Docker 테스트, 단절 표시 노드 테스트, tsc.
```

## 5. 홈 위젯 (Android) - 알림 없이 습관 고리

**착수 조건**: 리텐션 데이터가 "재방문 부족"을 가리킬 때. 매일 알림 금지 원칙을 우회하지 않는 유일한 상시 접점.

**실행 프롬프트:**
```
Android 홈 위젯을 구현해줘 (dev build 전제 - Expo Go 불가 확인 후 진행).
1. 소형 위젯 1종: 오늘 측정 전 "오늘 피부 기록 전" / 후 "오늘 82점" + 탭하면 앱(측정 전이면 촬영으로)
2. 데이터는 마지막 스캔 로컬 캐시 - 위젯에서 네트워크 호출 금지
3. 알림이 아니므로 매일 알림 금지 원칙과 충돌 없음을 주석 명시. 점수 외 정보(사진 등) 표시 금지
검증: tsc + 위젯 갱신 시점(측정 완료 직후) 확인 절차.
```

## 6. 다국어(영어) 확장

**착수 조건**: 국내 킬 크라이테리아 통과 후. strings.ts 단일 소스 구조라 전환 비용 낮음.

**실행 프롬프트:**
```
i18n 기반을 깔아줘. 실제 영어 번역은 별도 - 구조만.
1. strings.ts를 locale 사전 구조로 전환 (ko 기본, 타입은 ko 기준 keyof로 강제 - 누락 키 컴파일 에러)
2. 함수형 문구(verdictNotificationBody 등)도 locale별 함수로
3. 프롬프트(분석 evidence)는 한국어 고정 유지 - 영어 evidence는 프롬프트 버전업+재현성 게이트 필요함을 명시
검증: tsc (키 누락 시 컴파일 에러 재현 확인) + 기존 화면 문구 무변화 확인.
```

## 7. 웹 → 앱 퍼널 (마케팅 랜딩 - "웹 버전" 금지와 별개)

**착수 조건**: P0 처리방침 호스팅과 동시 가능 (같은 정적 호스팅에 얹음). W4 릴스 시작 전 완성 권장.
**구분**: 스코프 밖 "웹 버전"은 제품(측정·판정)의 웹 이식 - 촬영 통제 불가로 재현성 해자가 깨져 금지.
마케팅 랜딩은 관문일 뿐 제품이 아님 - 허용.

**실행 프롬프트:**
```
SkinMe 웹 랜딩 1페이지를 만들어줘 (정적, GitHub Pages/Vercel 무료 티어).
1. 구성: 히어로("거울은 매일 거짓말을 합니다") → 재현성 한 줄("같은 순간을 두 번 재면 같은 숫자") →
   공유 카드 샘플 이미지 → 스토어 설치 버튼(Play 우선) → 푸터에 개인정보처리방침(P0 겸용)
2. UI 원칙 준수: 화이트+민트 1색, 숫자 히어로, 이모지·일러스트 금지
3. UTM 파라미터 수용(릴스별 전환 측정 대비) - 분석 스크립트는 불필요, 링크 구조만
4. 공유 카드(ShareableScoreCard·ShareableCard) 하단에 랜딩 URL 한 줄 추가 - 바이럴→설치 연결
검증: 모바일 뷰포트 렌더 확인 절차. 앱 코드 변경은 공유 카드 URL 한 줄뿐.
```

## 검토했으나 보류 (사유 기록)

- **커뮤니티 (2026-07-06 재검토, 재보류)**: 트래픽 견인 목적으로 재검토했으나 - ① 유저 간 제품 추천으로
  중립성 해자("심판은 물건을 팔지 않는다")가 유저 손에 무너짐 ② 콜드스타트(빈 광장 = 죽은 앱 신호,
  트래픽 소비처지 견인책 아님) ③ 1인 모더레이션 비용 ④ 효능 UGC 법적 인접 리스크.
  재검토 조건: 판정 리포트 보유 유저 수천 명 시점에 "리포트 기반 대화"로 한정 설계.
  트래픽 견인은 커뮤니티가 아니라 웹 랜딩 퍼널(7번) + 공유 카드 + 릴스가 담당.

- **오프라인 촬영 큐** (네트워크 없을 때 찍어두고 나중에 분석): 사진을 기기에 보관해야 해서
  "분석 후 즉시 삭제" 원칙과 정면 충돌. 원칙이 우선 - 기각.
- **로그아웃 기능**: 익명 세션 특성상 로그아웃 = 데이터 접근 상실. 계정 연동(4-2) 완료 유저에게만
  의미 있음 - 연동 보급 후 재검토.
- **스킨케어 루틴 기록** (아침/저녁 사용 제품 일지): 판정 앱이 일지 앱으로 비대해지는 스코프 크리프.
  동시 추적 경고(2-2)가 같은 문제의 최소 해법 - 유저 요청이 반복될 때만 재검토.
- **1일/1주 판정, 커머스·추천**: CLAUDE.md 영구 금지 - 재검토 대상 아님.
